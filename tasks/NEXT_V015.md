# v0.1.5 — 白名单专注闭环试验（Phase 01B）

基线：phase01-poc / 1c1c903；v0.1.4 已有 USB 短测证据但拦截仍间歇性，Phase 01 未验收。用户已授权推进计时主页及白名单入口。此任务属于核心交互/兼容性联合验证，暂不合并 main，不启动完整分类、联网及正式产品开发。

## 目标
实现真实可用的短时白名单专注会话：用户选择允许应用 → 开始计时 → 计时主页显示任务和剩余时间 → 从主页打开允许应用 → 尝试进入已知不允许应用时被拦截/引导回主页 → 到期或明确应急退出后完全解除。使用同一会话状态，不因拦截层撤除、切页或短时辅助探测结束而误结束计时。保留原 Lab 黑名单及 T01–T12 诊断入口。

## 需求与范围
1. 专注主页：任务名（可选）、剩余时长、当前白名单图标/名称、打开应用、权限及管控状态、返回和应急结束。退出 UI、再打开、锁屏再解锁不得重启计时。不承诺系统解锁后自动强拉 Activity；先提供通知及正常桌面入口，任何额外自动回到主页行为单独实测。
2. 白名单：复用 AppCatalog，用户选取允许的普通可启动应用；保存模式配置和本次会话策略快照。已知普通可启动第三方应用默认受限；自身、桌面、输入法、拨号、系统安全界面等保护；未知/系统窗口放行并显示限制边界。不要在本轮自动分类、扩大对系统应用的管控或申请新的敏感权限。允许用户在会话开始前核对清单。
3. 状态解耦：计时生命周期、管控健康状态、当前窗口/拦截层生命周期独立；到期/明确停止/严重故障终止会话；常规窗口切换、拦截层安全超时只撤层并记录，不能无故结束会话。异常无法确认时 fail-open 并显式显示暂停管控/异常，不得将倒计时运行等同于管控有效。
4. 拦截：保留 A HOME 及 B 短时覆盖层实验，优先验证 A 是否能稳定退出已知受限应用，B 作为提示/备用；验证在系统允许且用户可安全退出情况下引导返回专注主页（先以可点击入口，后台 Activity 启动限制明确记录）。不延长覆盖层到不可退出，不遮挡系统设置、紧急页面、导航、权限撤销、卸载或强停。记录拦截尝试、动作接受、观察结果与延迟的区别。
5. 前台识别：修复 v0.1.4 辅助识别与60秒窗口的局限，先以显式 opt-in 的有界短测比较有/无 UsageStats 辅助；不读取节点、屏幕内容、通知正文，不保存原始使用轨迹。识别结果不确定时不猜测；不把最近5秒无事件当作当前应用确定。异步/节流查询，评估延迟与耗电。保留真实安全窗口放行，禁止通过过滤所有系统事件追求成功率。
6. 第一版限制会话10分钟（测试另有1/5分钟，保留原最长30分钟测试能力）；不实现全天多段调度、网络、严格退出锁定或 Device Owner。测试后再扩展。

## 验收（实机，APK 与 commit 绑定）
- P0 安全：必要系统界面、电话/应急、撤权、卸载、停止入口均可操作；无 INTERNET、读屏等禁止权限；故障放行、超期无拦截。
- P1 基础闭环：白名单2–3个非关键应用，非白名单2个普通应用，手动开启5分钟，白名单每个连续进出5次；受限应用通过桌面和最近任务各10次，共至少20次；记录每次实际结果，不把 HOME_REQUEST_ACCEPTED 当成功。目标受限20/20、白名单0误拦，未达标记录原因并修正；用户实际观察与事件延迟分别记录。
- P2 计时：开会话后打开允许应用、返回主页、锁屏/解锁、切换应用、覆盖层撤除，计时仍与原截止时间一致；到期及手动停止立即放行。测试当前正在受限应用时自动开始，分别有/无近期事件。
- P3 后台：5分钟后台、划掉最近任务、清理后台、锁屏30分钟（以独立原Lab测试），开机/重启和未来计划恢复继续按 T05–T11；不因新 UI 而跳过旧验收。无权限时明确提示。
- P4 回归：单元测试策略矩阵（白名单优先、已知受限、未知/系统保护、到期、停止、管控故障、撤层不结束计时），构建、Lint、最终 APK 权限审计；ADB 仅授权 debug 诊断，报告脱敏。

## 交付
可安装 v0.1.5 测试 APK、哈希、变更说明、一页中文逐步复测指南、量化报告（PASS/PARTIAL/FAIL/NOT RUN）、更新 ACTIVE/handoff。不要擅自标记 Phase 01 通过，不合并 main。若普通应用拦截仍不稳，先定位事件/状态差异，不继续堆界面或同步功能。

## 后续决策
白名单闭环 + 自动起止 + 后台/重启核心验收通过后：正式分类与模式配置（本地规则/可选授权外部分类），再多段日程与本地状态机，最后私有 LifeOS 数据源自动同步及授权回传。待实测决定是否需要可选启动器/其他正式方案，主力手机不直接配置设备所有者。
