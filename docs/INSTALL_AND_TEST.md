# Focus Lab 安装与真机操作

本版仅用于 Phase 01，版本 0.1.0-poc，Android 8.0/API 26 以上。MagicOS 11 的实际 Android API 在诊断页查看。测试包使用 debug 签名；不要作为正式长期管控版本。不同电脑/CI 产生的 debug 签名不同，覆盖安装不兼容时需卸载旧测试包（会清除数据）再装。

## 安装

1. 获取交付的 `lifeos-focus-lab-v0.1.0.apk` 与 `SHA256SUMS.txt`，先核对 SHA256。Windows：`Get-FileHash .\lifeos-focus-lab-v0.1.0.apk -Algorithm SHA256`。
2. 将 APK 传到手机，从文件管理器打开。按手机正常提示为该来源临时允许安装应用，再确认安装；完成后可关闭该来源的安装授权。遇系统限制请按系统界面处理。
3. USB 调试是可选方案：`adb install -r lifeos-focus-lab-v0.1.0.apk`。调试完成后可撤销 USB 调试授权。
4. 打开 LifeOS Focus Lab。屏幕顶部红色“停止所有测试”始终可用。先确认应用详情页、卸载、设置均可打开。

## 权限与安全

诊断页有设置入口。无障碍仅用于窗口包名识别与您指定应用的测试拦截；系统授权必须由您手动完成。若侧载应用被系统列为受限设置，阅读系统提示，在信任本次构建后按系统提供的正常入口授权。精确闹钟（Android 12+）、通知（Android 13+）分别授权。通知提供额外停止入口；没有通知权限仍可在 Lab 中停止。

首次保持默认电池及启动设置进行测试，随后再手动调整荣耀应用启动管理的自启动、关联启动、后台活动和电池优化，分别记录结果。Lab 不会自动修改系统设置。基础拦截不依赖使用情况访问或普通悬浮窗授权；这两项仅供“能力”页独立可选实验。无需全应用列表权限。

## 最短安全测试（约 5 分钟）

1. **诊断/T02**：启用无障碍，切换到几个应用再回 Lab，核对“最近外部窗口包名”。它仅保存在内存；事件累计数不等于真实应用切换次数。切换检测不需启动计时。
2. **应用/T01**：刷新、搜索，选择一个非关键第三方应用。系统应用、桌面、默认拨号器、输入法、设置、本应用不可选。不建议选通信、支付等日常关键应用。
3. **计时/T03-A、T04**：选择“返回桌面”，持续 1 分钟，立即开始。打开目标应收到返回桌面动作；未选应用正常。回 Lab 点停止，再打开目标应恢复正常。重做一次等待自然到期。动作请求被系统接受与肉眼看到桌面是两种证据，要分别记录。
4. **计时/T03-B**：选择覆盖层，持续 1 分钟，打开目标。覆盖层有返回桌面和立即停止按钮；持续显示 10 秒将自动停止本次会话，这是实验安全限制。需要复测时重新开始。若系统新窗口事件可见会自动移除；锁屏或失效状态也移除。
5. **计时/T05**：相对计划设为 2 分钟后开始、持续 1 分钟。观察开始/结束并记录真实时间。也可选未来 24 小时内的绝对日期/时间，结束由持续分钟确定，可跨午夜。未授精确闹钟时明确降级为非精确调度，不据此宣称精确测试通过。
6. **报告**：按实际测试逐项选择 PASS/PARTIAL/FAIL/NOT RUN，生成预览、检查后手动选择文件位置导出 JSON。导出的测试应用只有代号、无名称/包名。补充样本数、成功率及子场景到 `tests/PHASE01_REPORT.md` 的个人副本；不要把真实应用清单提交到公开仓库。

## 完整验收

继续按 [PHASE01_TEST_PLAN.md](../tests/PHASE01_TEST_PLAN.md) 和 [扩展矩阵](../tests/PHASE01_CAPABILITY_MATRIX.md) 执行 T01–T12，包含 20 次普通切换/拦截、通知/链接进入、锁屏、省电、飞行模式、划掉任务、长待机、撤权、重启、时间改变、小窗/分屏/分身。长时间后台测试可设置未来时段，单次限制最长 30 分钟；请用非关键目标。禁止实际拨打紧急号码。

报告日志固定为最多 100 条本地诊断：连接、状态切换、闹钟回调偏差、动作请求结果及错误代码。`delta_ms` 在闹钟记录中表示实际回调减预定时间；HOME/覆盖层记录中表示事件到动作请求的时间，不是可见拦截延迟。不会持续保存所有应用打开历史。可清除日志或停止并删除全部配置、结果。手动导出的文件需要自行删除。

## 已知边界

- 无障碍不阻止应用进程启动；普通全屏、分屏、小窗和厂商特殊窗口效果均待验证。
- 自动开始只在有最近 5 秒的已知前台窗口时尝试立即拦截；否则等待新窗口事件，不读取当前屏幕节点。不保证目标长时间静止在前台时立即处理。
- 覆盖层是 10 秒安全试验，不是正式连续拦截界面；打开系统界面或未知窗口时优先放行。系统若不发送窗口事件，可能短暂遮挡，最多 10 秒；系统通知栏/权限界面能力需实测。
- 手动计时使用 elapsedRealtime，修改系统时间不延长同次启动的计时；重启或无法确认启动周期时取消。计划使用绝对时间，手动改时钟会按新时间重新判断。
- 设备重启后，凭系统 BOOT_COMPLETED、服务重连、打开 Lab 等恢复有效计划，不在首次解锁前锁定。强行停止后 Android 可能不再发广播/闹钟，需手动打开 Lab；不会绕过。
- 不使用前台服务永久常驻或读屏能力；UsageStats 和短时前台服务仅供独立实验。后台存活、短间隔 Doze 闹钟配额及厂商清理效果需要实测。日志最多 100 条，长测试前先导出/清空。

## T09–T12 能力页操作

- **使用情况访问**：单独打开系统授权页，返回后点击“仅本次读取最近60秒”。只查询包名/事件类型/时间及系统聚合使用时长，在页面内存展示、最多60秒后清除，不写入日志或报告。聚合接口按系统时间桶返回，可能超出60秒查询范围；不能把聚合数值当成精确测量。对照人工计时记录误差，随后撤权再试。
- **普通悬浮窗**：单独授权后点10秒实验。黄色非触摸提示仅在Lab前台显示，10秒或Lab失去前台即移除，避免覆盖安全设置。此实验只比较窗口创建/移除，不验证跨应用后台遮挡。基础拦截采用无障碍覆盖层，不依赖此权限；未证明必要前不推荐正式版保留普通悬浮窗。
- **前台服务**：从可见Lab页面启动60秒实验，再切后台观察通知、停止入口与系统任务管理器行为。Android14+使用shortService，不伪装其他服务类型；到期停止，不自动重启。先设置计划再启动实验（修改会话会停止其他实验），它只覆盖前60秒，不能证明长期保活。系统拒绝/停止需如实记为限制。
- **屏幕固定**：先阅读系统的解除手势/按键提示，再点击并由系统确认。仅固定Lab，60秒后尝试解除，顶部停止按钮亦可解除；系统设置、导航方式和确认对话框以实机为准。已经处于受管白名单时拒绝启动此实验，不配置Device Owner。屏幕固定不是多应用管控的等价方案。
- **退出摩擦**：独立60秒模拟会话只演示普通退出的5秒确认等待；应急按钮立即解除，不限制系统导航/设置。没有持续拦截功能，不影响其他应用。
- **设置及绕行**：标准Android设置包出现时仅记固定诊断代码，不读取子页面，全部放行；无法区分厂商设置页、Home/Overview时不猜测。按矩阵手动测试各入口，在报告页记录T10；不覆盖或拦截权限、安全或紧急页面。
- **荣耀配置与组合**：能力页“开/关/未知”只记录您手动确认，不是自动授权检测。按矩阵分别增量改变配置，对照默认、基础权限、完整配置三组，记录T11。开机恢复使用系统广播，不绕过强停。
- **模拟JSON**：载入跨日连续时段文本，验证带时区的起止边界，再用文件选择器导出；可将导出文本粘回输入框验证往返。仅校验模拟数据，不导入真实日程、不注册多段真实管控、不访问云端账号。真实多段计划执行属于后续阶段。

相关平台依据：[短时前台服务](https://developer.android.com/develop/background-work/services/fgs/service-types)、[屏幕固定与受管Lock Task区别](https://developer.android.com/work/dpc/dedicated-devices/lock-task-mode)。

## 从源码构建

使用 JDK 21、Gradle 8.13、Android SDK Platform 35 / Build Tools 35.0.0、AGP 8.9.2、Kotlin/Compose 编译插件 2.1.20；Compose UI/Foundation 1.7.8、Material3 1.3.2、Activity Compose 1.10.1，依赖版本固定。构建工具联网下载依赖，手机 APK 本身无网络权限。

在 `android/local.properties` 设置本机 `sdk.dir`（不提交），然后：

```powershell
cd android
.\gradlew.bat --no-daemon testDebugUnitTest lintDebug assembleDebug
cd ..
py -3 tools/audit.py android/app/build/intermediates/merged_manifests/debug/processDebugManifest/AndroidManifest.xml
py -3 tools/audit.py android/app/build/outputs/apk/debug/app-debug.apk <SDK目录>/build-tools/35.0.0/aapt.exe
```

CI 在 phase01-poc 推送或 PR 时构建、单元测试、Lint、权限审计并保存 APK 和哈希 artifact 7 天。无真实设备测试。未经真机验收不合并 main、不推进 Phase 02。

平台接口依据：[Android 闹钟文档](https://developer.android.com/develop/background-work/services/alarms)、[精确闹钟授权](https://developer.android.com/about/versions/14/changes/schedule-exact-alarms)、[无障碍服务](https://developer.android.com/guide/topics/ui/accessibility/service)。OEM 实际表现以本测试为准。
