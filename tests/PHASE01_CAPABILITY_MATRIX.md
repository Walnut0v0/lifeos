# Phase 01 扩展：完整系统能力与授权矩阵

本文件为第一阶段强制验收范围，与 PHASE01_TEST_PLAN.md 共同执行。目标是在一次 Lab 开发中验证最终产品可能依赖的全部合理系统能力，而非仅测试番茄钟。所有项目分别标记 AVAILABLE / PARTIAL / UNAVAILABLE / NOT RUN / NOT APPLICABLE；不能获取状态时显示“需手动确认”，不伪造授权结果。每项记录 API、授权方式、是否必要、拒绝/撤销结果、默认及授权后表现、设备/系统版本、恢复方式。禁止为“测试全部权限”申请无关敏感权限。独立测试开关，默认关闭，测试结束恢复初始配置。

## T09 授权与厂商适配矩阵
|能力|候选接口/配置|实测项目|
|---|---|---|
|无障碍|AccessibilityService|侧载授权、连接/断连、重连、权限撤销、最小事件范围|
|使用情况访问|UsageStatsManager / PACKAGE_USAGE_STATS / AppOpsManager|用户独立授权；前台应用识别、事件完整性、时长误差、延迟、锁屏/重启、缺权降级；仅本地测试元数据|
|应用查询|PackageManager / launcher queries|主要应用、分身/工作资料、分类字段；记录不可见范围，不默认全包权限|
|精确闹钟|AlarmManager.canScheduleExactAlarms / SCHEDULE_EXACT_ALARM|开始/结束、授权变更、Doze 限频、时钟/时区变化|
|通知|POST_NOTIFICATIONS / NotificationManager|授权、渠道开关、锁屏显示、持续通知及应急停止；不读取其他通知|
|前台服务|FOREGROUND_SERVICE 与合法适用的服务类型|仅在符合 SDK 规则且确有必要时测试；后台启动限制、通知、用户停止、资源开销|
|无障碍覆盖层|TYPE_ACCESSIBILITY_OVERLAY|显示/移除、遮挡范围、触摸与返回、锁屏安全；不默认申请额外悬浮窗权限|
|普通悬浮窗|SYSTEM_ALERT_WINDOW / Settings.canDrawOverlays|仅独立可选对比实验，证明必要才保留；禁止覆盖权限、安全、紧急界面|
|开机广播|RECEIVE_BOOT_COMPLETED / BOOT_COMPLETED|首次启动后、重启、首次解锁、重新注册任务，区分普通重启和强制停止；直接启动仅在确有必要时评估，不在解锁前启动限制|
|电池优化豁免|PowerManager.isIgnoringBatteryOptimizations|默认/豁免、拒绝/撤销、Doze、省电、待机；用户手动授权，非无条件保活|
|荣耀自启动|应用启动管理：允许自启动|关闭/开启，重启及解锁后是否收到广播/恢复|
|荣耀关联启动|应用启动管理：允许关联启动|关闭/开启，系统事件后能否恢复|
|荣耀后台活动|应用启动管理：允许后台活动|关闭/开启，后台、锁屏、清理、待机|
|荣耀多任务卡片加锁|用户在多任务界面手动加锁|加锁前后划卡、清理全部、锁屏、重启的差异；记录可否读取状态，不自动操作厂商设置|
|后台弹出界面|厂商后台弹出/显示界面设置（若存在）|是否可从后台显示自有提示，系统限制与替代方案；不依赖强行拉起 Activity|
|屏幕固定|系统 screen pinning / startLockTask|用户主动启用、正常退出、通知/返回/主页/多任务表现；只做短时可逆演示|
|设备管理|DevicePolicyManager / Lock Task 能力调查|读取当前是否存在管理角色、是否支持受管设备；普通个人手机不授予 Device Owner，不修改设备管理状态；高级验证另用模拟器/专用测试机并经单独同意|

权限面板应显示状态、检测方法、用途、授权入口（若公开 Intent 可用）、手动配置说明、最近检查时间、测试结果与撤销后的降级策略。厂商专有选项没有公开可靠查询接口时，保留用户手动确认和实际行为验证。禁止反射隐藏 API、自动点击授权页面或宣称不可检测的设置已开启。

## T10 防退出与管控绕行场景
需求：评估专注期间通过系统设置、多任务等途径中断约束的可能性，并确定可逆的防冲动退出策略。区分“退出 Lab UI”“清除任务卡片”“停止无障碍服务/强制停止”“撤销权限/卸载”。这些操作不等价。
- 设置：从桌面、快捷设置、应用详情、通知、系统管家等入口进入，测试仅包名/允许的事件能否识别设置相关窗口。测试普通设置入口的限时退出确认或提示（用户可立即明确解除并进入设置）；权限管理、紧急与安全设置始终可达。不得通过遮盖、自动返回循环或阻断系统安全控制来阻止撤权/卸载/强停；如果不能区分普通设置与必要页面，则直接放行。
- 多任务：手势与三键导航分别测试，检测能否区分桌面、最近任务、分屏和小窗（仅包名不足时记录不可区分）；测试用户手动多任务卡片加锁是否减少一键清理；短时系统屏幕固定演示可否限制最近任务入口，验证正常退出。普通专注模式不拦截整个系统桌面或 SystemUI，不使用全屏覆盖层封锁导航。
- 其他路径：Home/Back、快捷面板、通知跳转、深链、分屏、小窗、应用分身、桌面小组件、语音助手、浏览器内替代内容；分别标记能否检测/限制/恢复，不读取页面内容。主动强停、撤权、卸载、清除数据后记录管控是否终止及再次手动启动的恢复，不尝试规避。
- 退出摩擦：Lab 内模拟延迟确认与明确应急停止，独立测试 60 秒短会话；保留安全解除，禁止无限重试、后台隐藏、阻止用户最终控制设备。
- 受管设备方案：查明 Android Enterprise Lock Task 对 Overview、Home、通知的可配置能力及其 Device Owner/DPC 前置条件。在普通主力手机上仅报告可行性/风险；如需真实高级模式，另行征得同意并使用专用测试设备或模拟器，必须有恢复方案。不能将屏幕固定当作多应用白名单的等价实现。

## T11 开机与后台组合实验
对照至少三组：默认权限；基础权限（无障碍/精确闹钟/通知）；基础权限 + 荣耀手动启动管理三项 + 电池优化豁免 + 多任务加锁（每项分别增量验证，有差异则记录）。每组测试后台 5min、清理、锁屏 30min、重启/首次解锁；完整配置追加锁屏 2h、夜间待机、普通/超级省电（若有）、低电量、充电/未充电、飞行模式、断网、时钟变动。记录进程、无障碍连接、Alarm 回调、实际管控状态、恢复延迟，区分 UI 是否仍在最近任务和服务是否工作。故障/过期必须放行；停止后取消所有测试定时器和覆盖层。强停后无法自动恢复属于系统限制，不得宣称保活成功。

## T12 未来功能基础能力
验证 UsageStats 授权下可读取使用事件及聚合时长（对照人工计时，区分前台/屏幕熄灭/多窗口；默认不保留完整轨迹）；扫描应用系统分类覆盖率；本地配置持久化、导入导出模拟 JSON、跨日/时区/连续计划、数据清除、报告预览。同步网络及 OAuth 仅列后续验证项：Phase 01 APK 不含 INTERNET，不访问真实账号或云端。

## 最终交付和验收
Lab 提供权限总览、T01–T12 独立入口和报告导出；新增授权矩阵和绕行矩阵，输出每个候选机制的必要性、有效性、风险、配置成本、局限和后续推荐。所有普通手机可安全实测的能力须实际提供可操作测试入口/步骤；受系统权限限制或需专用设备的项目记录原因和替代验证，不能强行取得全部授权。所有安全项必须通过；实机测试未执行不得标通过。保留 Phase 01 离线和最小权限约束，禁止无关敏感权限。
